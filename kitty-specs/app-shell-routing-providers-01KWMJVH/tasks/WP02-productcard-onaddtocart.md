# WP02 — `ProductCard.onAddToCart` (entity UI refinement)

## Objective

Add an **optional**, backward-compatible `onAddToCart?: () => void` to `ProductCardProps`. When the callback is provided, render an Add-to-cart `Button`; when absent, render the card exactly as it looks today. This is the entity-UI enabler that WP05 (HomeContainer) needs to wire the add-to-cart use case.

## Context

**Why a separate WP**: The card is an entity-layer UI component used both by the existing `HomePage` (no callback) and the new `HomeContainer` (with callback). The change must be strictly additive — C-004 forbids regressing the existing page boundary, and the existing `home-page.tsx` calls `<ProductCard {...product} />` without `onAddToCart`.

**Codebase facts** (verified 2026-07-03):

- The current file is at `src/entities/product/ui/ProductCard/ProductCard.tsx` and exports `ProductCard` plus `ProductCardProps`.
- Current `ProductCardProps`:
  ```ts
  export interface ProductCardProps {
    skuId: string
    name: string
    imageUrl: string
    listPriceCents: number
    salePriceCents: number | null
    isLoading?: boolean
  }
  ```
- The card's layout is a vertical flex (`flex w-full flex-col gap-3 ... rounded-lg bg-card p-3 shadow-subtle`) containing an image block and a `<div className="flex flex-col gap-1">` with the title and `PriceBlock`.
- The project's `Button` primitive lives at `@/shared/ui` (re-exported from `src/shared/ui/index.ts`). It accepts `{ variant, size, disabled, onClick, children }`. `variant="default"` is the solid primary style.
- The card uses `Money.fromCents(cents).format()` for prices — keep this unchanged.
- An existing `ProductCard.stories.tsx` lives next to the component. There is also `src/entities/product/ui/ProductCard/index.ts` re-exporting the component and props.

**FSD note**: This is an entity-layer file. The card may import from `@/shared/ui` (lower layer) for the Button. It must **not** import from features/widgets/pages/app.

## Subtask T005 — Render Add-to-cart `Button` when `onAddToCart` is present

**Purpose**: Surface the action only when a handler is supplied; preserve the card's current appearance when it isn't.

**File**: `src/entities/product/ui/ProductCard/ProductCard.tsx`.

**Steps**:

1. Import the `Button`:
   ```tsx
   import { Button } from '@/shared/ui'
   ```

2. Add a new prop `isOutOfStock?: boolean` **only if needed**. Decision: do **not** add it here. Out-of-stock presentation is owned by the container (WP05), which simply does not render an enabled button — it passes a no-op or omits `onAddToCart` for out-of-stock items. Keep this WP focused on the positive case.

3. Inside the non-loading return, after the `<div className="flex flex-col gap-1">...</div>` block, conditionally render the button. Use the existing card flex column so the button sits at the bottom:
   ```tsx
   {onAddToCart !== undefined && (
     <Button
       type="button"
       variant="default"
       size="sm"
       onClick={onAddToCart}
       className="mt-1 w-full"
     >
       Add to cart
     </Button>
   )}
   ```

4. **No layout shift when absent**: The conditional render means existing usages (no `onAddToCart`) render exactly the markup they render today — verified by diffing the output of the existing stories before/after.

**Design fidelity**: There is no Penpot design for an add-to-cart button on the product card (the design file contains no Home/page grid). Use `Button` with `variant="default"` and `size="sm"` for a compact, primary action. This satisfies C-007 (no new primitives, no new tokens).

**Validation**:
- [ ] When `onAddToCart` is omitted, the rendered DOM is byte-identical to today.
- [ ] When provided, the button is keyboard-accessible (it's a `Button`) and announces "Add to cart".
- [ ] `mt-1 w-full` are existing Tailwind utilities (no new classes).
