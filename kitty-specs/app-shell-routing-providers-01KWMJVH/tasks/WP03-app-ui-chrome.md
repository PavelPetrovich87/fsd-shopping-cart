# WP03 — App UI Chrome (Header, CartIcon, Routes)

## Objective

Build the persistent application chrome: a global header with Home/Cart navigation and a cart-icon badge that reactively reflects the cart's distinct-item count, plus the route table that mounts the Home/Cart containers and redirects unknown paths to `/`.

## Context

**Why this WP**: FR-002 (routing), FR-003 (header + cart icon), FR-004 (badge reactivity), NFR-001 (responsive), NFR-003 (instant nav). These three files are the skeleton every routed page lives inside.

**Codebase facts** (verified 2026-07-03):

- `react-router-dom` v7 is already a dependency and already in use: `src/main.tsx` wraps `<BrowserRouter>` around `<App />`, and `src/App.tsx` renders `<Routes>`. Use the same imports the rest of the app uses (`Routes`, `Route`, `Link`, `NavLink`, `Outlet`, `Navigate` from `react-router-dom`).
- The reactive cart hook is `useCart()` from `@/entities/cart/api/cart-store`. It returns the live `Cart` object and re-renders consumers on every cart change.
- Distinct-item count helper: `getUniqueItemCount(cart)` from `@/entities/cart` (this counts line items, **not** sum of quantities — per spec Assumption and IC-02). Use this for the badge.
- The presentational pages live at `@/pages` (`HomePage` from `@/pages/home`, `CartPage` from `@/pages/cart`). **However**, the routes here point at the *containers* (`HomeContainer`, `CartContainer`) created by WP04/WP05, not the presentational pages directly. The containers live at `@/app/containers/...`. Because WP04/WP05 land in separate worktrees, this WP must **import the containers lazily** to avoid a hard dependency at build time, OR this WP's `AppRoutes` is updated by WP07 at assembly time. **Decision**: this WP defines `AppRoutes` to import from `@/app/containers/home-container` and `@/app/containers/cart-container` — those paths are the contract WP04/WP05 will satisfy. If they aren't merged yet at lint time, WP07 owns the integration. For local validation, you may create thin stub container files inside this WP's worktree at those paths and remove them before merge — but **only if** doing so does not collide with `owned_files`. Preferred: leave the imports pointing at the agreed paths and let WP07 sequence the merge.
- The Penpot file has **no header/nav/cart-icon design** (verified at specify time). Compose the header from existing tokens: `bg-white border-b border-neutral-200`, max-width container `max-w-6xl mx-auto px-4 py-3`. This satisfies C-007 (no new tokens/primitives).
- `Cart` type fields available: `cart.items` is a `Map<string, CartItem>`; `getUniqueItemCount(cart)` returns a number.

**FSD constraint**: The app layer may import from `entities`, `shared`, `pages`, `widgets`, `features`. The containers are intra-app imports (`./containers/...` or `@/app/containers/...`) — allowed.

## Subtask T007 — Create `CartIcon` bound to `getUniqueItemCount(useCart())`

**Purpose**: A self-contained header element that shows the cart glyph with a numeric badge; the badge reflects the distinct-item count and updates in one render cycle.

**File**: `src/app/ui/cart-icon.tsx` (new).

**Steps**:

1. Imports:
   ```tsx
   import { Link } from 'react-router-dom'
   import { useCart } from '@/entities/cart/api/cart-store'
   import { getUniqueItemCount } from '@/entities/cart'
   ```

2. Component:
   ```tsx
   export function CartIcon() {
     const cart = useCart()
     const count = getUniqueItemCount(cart)
     return (
       <Link
         to="/cart"
         aria-label={`Cart, ${count} item${count === 1 ? '' : 's'}`}
         className="relative inline-flex items-center gap-1 text-sm font-medium text-neutral-700 hover:text-neutral-900"
       >
         <span aria-hidden="true" className="text-base">🛒</span>
         <span className="hidden sm:inline">Cart</span>
         {count > 0 && (
           <span
             aria-hidden="true"
             className="absolute -right-2 -top-2 inline-flex h-5 min-w-5 items-center justify-center rounded-full bg-error-600 px-1 text-xs font-semibold text-white"
           >
             {count}
           </span>
         )}
     </Link>
     )
   }
   ```

3. **Badge semantics**: `count === 0` → no badge rendered (don't show a "0"). The badge number is `getUniqueItemCount` (distinct items). Use the existing `bg-error-600` token (verify with `grep 'bg-error-600\|text-error-600' dist/assets/index-*.css` after building, per AGENTS.md step 12 — this token is already used by `PriceBlock` in `ProductCard`).

4. **Accessibility**: `aria-label` includes the count for screen readers; the visible "Cart" text is hidden on mobile (`hidden sm:inline`) to save space at 375px.

**Validation**:
- [ ] Badge shows the correct number after `useCart()` changes (e.g., add an item via the store in a unit test).
- [ ] Badge is hidden when cart is empty.
- [ ] `Link to="/cart"` navigates without a full page reload.
- [ ] No new Tailwind classes that don't already exist in the build.

## Subtask T008 — Create `AppLayout` (header nav + `<CartIcon />` + `<Outlet />`)

**Purpose**: The persistent chrome that wraps every routed page.

**File**: `src/app/ui/layout.tsx` (new).

**Steps**:

1. Imports:
   ```tsx
   import { NavLink, Outlet } from 'react-router-dom'
   import { CartIcon } from './cart-icon'
   ```

2. Component — header with nav links and the cart icon, then the routed page below:
   ```tsx
   export function AppLayout() {
     return (
       <div className="min-h-screen bg-neutral-50">
         <header className="border-b border-neutral-200 bg-white">
           <nav className="mx-auto flex max-w-6xl items-center justify-between px-4 py-3">
             <div className="flex gap-4">
               <NavLink
                 to="/"
                 end
                 className={({ isActive }) =>
                   `text-sm font-medium ${isActive ? 'text-neutral-900' : 'text-neutral-500 hover:text-neutral-900'}`
                 }
               >
                 Home
               </NavLink>
               <NavLink
                 to="/cart"
                 className={({ isActive }) =>
                   `text-sm font-medium ${isActive ? 'text-neutral-900' : 'text-neutral-500 hover:text-neutral-900'}`
                 }
               >
                 Cart
               </NavLink>
             </div>
             <CartIcon />
           </nav>
         </header>
         <Outlet />
       </div>
     )
   }
   ```

3. **Responsive** (NFR-001): At 1440/768/375 px, the header is a single row (`flex items-center justify-between`). The `max-w-6xl mx-auto px-4` container matches the existing pages' own container. The header does not collapse to a hamburger for this mission (no design, no new primitive). On 375px the visible "Cart" label is hidden (T007) but the icon+badge remain, preserving the action.

4. **Why `NavLink` not `Link`**: `NavLink` provides active-state styling out of the box, signalling "you are here" (good for accessibility and matches the demo's behaviour in `pages/App.tsx`).

**Validation**:
- [ ] Header renders on both `/` and `/cart`.
- [ ] Active link uses `text-neutral-900`; inactive uses `text-neutral-500`.
- [ ] `<Outlet />` renders the matched child route.
- [ ] Header is responsive at 1440/768/375 (visual check via Storybook or dev server).

## Subtask T009 — Create `AppRoutes` (`/`, `/cart`, `*` → `/`)

**Purpose**: The route table.

**File**: `src/app/routing/routes.tsx` (new).

**Steps**:

1. Imports:
   ```tsx
   import { Routes, Route, Navigate } from 'react-router-dom'
   import { AppLayout } from '../ui/layout'
   import { HomeContainer } from '../containers/home-container'
   import { CartContainer } from '../containers/cart-container'
   ```

2. Component:
   ```tsx
   export function AppRoutes() {
     return (
       <Routes>
         <Route element={<AppLayout />}>
           <Route path="/" element={<HomeContainer />} />
           <Route path="/cart" element={<CartContainer />} />
           <Route path="*" element={<Navigate to="/" replace />} />
         </Route>
       </Routes>
     )
   }
   ```

3. **Unknown routes redirect to `/`** (per US-2 acceptance scenario 3 and FR-002's default-route behaviour). `Navigate` with `replace` keeps history clean.

4. **Container import contract**: WP04 owns `src/app/containers/cart-container.tsx` and exports `CartContainer`; WP05 owns `src/app/containers/home-container.tsx` and exports `HomeContainer`. These are the agreed public names. If those WPs have not landed in your worktree's base, you have two options (pick one and document it in your WP commit message):
   - (a) **Preferred — defer**: leave the imports as written; WP07 (assembly) is responsible for landing this only after WP04/WP05 merge. `lint:arch` and `build` for this WP in isolation would fail on the missing imports — that's expected; flag it in the WP07 prompt.
   - (b) **Local stubs**: create minimal `export function HomeContainer() { return null }` stubs at those paths **inside a scratch directory** and adjust imports to point there. Do **not** commit stubs at the real container paths — that would collide with WP04/WP05's `owned_files`.

   Choose (a) unless the orchestrator's lane model requires this WP to build standalone.

**Validation**:
- [ ] `/` renders `HomeContainer` inside `AppLayout`.
- [ ] `/cart` renders `CartContainer` inside `AppLayout`.
- [ ] `/anything-else` redirects to `/` (URL becomes `/`).
- [ ] Browser back/forward works after navigation (US-2 scenario 2).

- **Risk**: Using `getItemCount` (sum of quantities) instead of `getUniqueItemCount` (distinct items). **Reviewer**: confirm the badge uses `getUniqueItemCount` — this is the most-cited requirement trap.
- **Risk**: Hard-coding a hamburger menu or drawer that doesn't exist as a primitive. **Reviewer**: confirm no new shared UI is introduced (C-007).
- **Risk**: Forgetting `end` on the root `NavLink to="/"`, which would make it active on every route. **Reviewer**: confirm `<NavLink to="/" end>`.

- **Risk**: `Route path="*"` with `element={<HomeContainer />}` instead of `<Navigate>` — the spec mandates a redirect (US-2 scenario 3). **Reviewer**: confirm `Navigate to="/" replace`.
