# WP04 — Cart Container

## Objective

Bridge the live cart aggregate to the presentational `CartPage`. Derive every presentational prop (`CartListItem[]`, subtotal, discount, shipping, total, applied coupon) from the cart via the `Money` value object — never by parsing display strings. Wire every cart callback to its use case. Handle all four `InitiateCheckout` outcomes (success, empty_cart, invalid_state, stock_conflict).

This WP is the cart half of US-1 and all of US-3.

## Context

**Codebase facts** (verified 2026-07-03):

- `CartPage` props (the contract you must feed — do **not** change it; C-004):

- `AppliedCoupon`: `{ code: string, discountLabel: string }`.
- The live cart: `useCart()` from `@/entities/cart/api/cart-store` returns `Cart`. `Cart.items` is a `Map<string, CartItem>`.
- `CartItem`: `{ skuId, name, unitPriceCents: number, quantity, createdAt }`.
- Product display data: `productsData` from `@/shared/api` (an array of `Product` with `description`, `imageUrl`, etc.). Join by `skuId`.
- Cart helpers from `@/entities/cart`: `getSubtotalCents(cart)`, `getUniqueItemCount(cart)`, `getItemCount(cart)`.
- `Money` from `@/shared/lib`: `Money.fromCents(cents).format()` → e.g. `"$12.00"`. Money also supports `.subtract`, `.multiply`, `.cents`.
- **`Coupon` discount API (resolved open detail)**: a `Coupon` instance exposes `calculateDiscount(subtotal: Money, now: Date, eventBus?) → Money`. It already handles flat vs percentage, capping, and clamping. **Do not** look for `amountCents` — it does not exist on the public API. Look up the coupon via `couponRepo.findByCode(code)` (returns `Promise<Coupon | null>`). `coupon.code`, `coupon.discountMode` ('flat' | 'percentage'), and `coupon.discountAmount` (`Money | undefined`, only for flat) are available if needed for the label, but `calculateDiscount` is the canonical computation.
- Use cases (all async; import from their feature slices):
  - `ChangeCartItemQuantity(skuId, newQuantity, cartRepo, stockRepo, eventBus)` — `@/features/cart-actions`
  - `RemoveFromCart(skuId, cartRepo, eventBus)` — `@/features/cart-actions`
  - `ApplyCoupon(code, cartRepo, couponRepo, eventBus)` — `@/features/apply-coupon`
  - `RemoveCoupon(cartRepo, eventBus)` — `@/features/apply-coupon`
  - `InitiateCheckout(cartRepo, stockRepo, eventBus)` — `@/features/checkout`
- `InitiateCheckoutResult`:
  - `{ success: true; cart: Cart }`
  - `{ success: false; reason: 'empty_cart' }`
  - `{ success: false; reason: 'invalid_state' }`
  - `{ success: false; reason: 'stock_conflict'; conflicts: StockConflict[] }`
- `StockConflictModal` from `@/features/checkout`: props `{ open: boolean, conflicts: StockConflict[], onAcknowledge: () => void }`. `StockConflict` is `{ skuId, productName, requestedQuantity, availableQuantity, imageUrl? }`.
- `Modal` from `@/shared/ui`: props `{ open: boolean, onClose: () => void, title: string, children: ReactNode }`.
- `Button` from `@/shared/ui`.
- `useAppDeps()` from `@/app` (WP01) provides `{ eventBus, cartRepo, stockRepo, couponRepo }`.

**Shipping rule** (presentation-only constant, lives in this container): when the cart has items, shipping is a flat `$12.00` (`SHIPPING_FLAT_CENTS = 1200`); when the cart is empty, shipping is `undefined`. This matches the demo in `src/pages/App.tsx` and is the established UX.

## Subtask T012 — Derive order summary (subtotal/discount/shipping/total) via `Money`

**Purpose**: Produce the four summary strings + `appliedCoupon` from the cart and the coupon repo, all via `Money`.

**File**: `src/app/containers/cart-container.tsx` (same file, continue).

**Steps**:

1. Subtotal (synchronous):
   ```tsx
   const subtotalCents = getSubtotalCents(cart)
   const subtotal = Money.fromCents(subtotalCents).format()
   ```

2. Shipping:
   ```tsx
   const hasItems = cart.items.size > 0
   const shipping = hasItems ? Money.fromCents(SHIPPING_FLAT_CENTS).format() : undefined
   ```

3. Discount + appliedCoupon (async — depends on coupon lookup). Use local state:
   ```tsx
   const [discountCents, setDiscountCents] = useState<number | undefined>(undefined)
   const [appliedCoupon, setAppliedCoupon] = useState<AppliedCoupon | undefined>(undefined)

   useEffect(() => {
     let cancelled = false
     const code = cart.couponCode
     if (!code) {
       setDiscountCents(undefined)
       setAppliedCoupon(undefined)
       return
     }
     couponRepo.findByCode(code).then((coupon) => {
       if (cancelled || !coupon) {
         setDiscountCents(undefined)
         setAppliedCoupon(undefined)
         return
       }
       const subtotalMoney = Money.fromCents(subtotalCents)
       const discountMoney = coupon.calculateDiscount(subtotalMoney, new Date())
       setDiscountCents(discountMoney.cents)
       setAppliedCoupon({
         code: coupon.code,
         discountLabel: `-${discountMoney.format()}`,
       })
     })
     return () => { cancelled = true }
   }, [cart.couponCode, subtotalCents, couponRepo])
   ```

4. Derived display strings from the resolved cents:
   ```tsx
   const discount = discountCents !== undefined ? `-${Money.fromCents(discountCents).format()}` : undefined
   const totalCents =
     subtotalCents - (discountCents ?? 0) + (hasItems ? SHIPPING_FLAT_CENTS : 0)
   const total = Money.fromCents(Math.max(0, totalCents)).format()
   ```

**Validation**:
- [ ] No number is reconstructed from a string anywhere (SC-004).
- [ ] Discount label uses the `coupon.calculateDiscount` result via `Money.format()`.
- [ ] Empty cart → `discount` undefined, `shipping` undefined, `total` equals `$0.00` derived from `Money.fromCents(0)`.
- [ ] The effect cleans up (no setState after unmount — `cancelled` guard).

## Subtask T013 — Wire cart callbacks to use cases

**Purpose**: Each `CartPage` callback invokes the corresponding use case with the injected deps.

**File**: `src/app/containers/cart-container.tsx` (continue).

**Steps**:

1. Acquire deps:
   ```tsx
   const { cartRepo, stockRepo, couponRepo, eventBus } = useAppDeps()
   ```

2. Define stable callbacks (`useCallback` with the deps they close over):
   ```tsx
   const handleIncrement = useCallback(
     (skuId: string) => {
       const item = cart.items.get(skuId)
       if (!item) return
       ChangeCartItemQuantity(skuId, item.quantity + 1, cartRepo, stockRepo, eventBus)
     },
     [cart, cartRepo, stockRepo, eventBus],
   )

   const handleDecrement = useCallback(
     (skuId: string) => {
       const item = cart.items.get(skuId)
       if (!item) return
       ChangeCartItemQuantity(skuId, item.quantity - 1, cartRepo, stockRepo, eventBus)
     },
     [cart, cartRepo, stockRepo, eventBus],
   )

   const handleRemove = useCallback(
     (skuId: string) => {
       RemoveFromCart(skuId, cartRepo, eventBus)
     },
     [cartRepo, eventBus],
   )

   const [couponError, setCouponError] = useState<string | undefined>(undefined)

   const handleApplyCoupon = useCallback(
     (code: string) => {
       setCouponError(undefined)
       ApplyCoupon(code, cartRepo, couponRepo, eventBus).then((result) => {
         if (!result.success) setCouponError(result.error.message)
       })
     },
     [cartRepo, couponRepo, eventBus],
   )

   const handleRemoveCoupon = useCallback(() => {
     setCouponError(undefined)
     RemoveCoupon(cartRepo, eventBus)
   }, [cartRepo, eventBus])
   ```

3. **Fire-and-forget async**: the use cases mutate the store, which triggers `useCart()` to re-render this container. You don't need to await them in the click handlers; however, for `ApplyCoupon` we read the `result` to surface a coupon error.

4. `onEmptyStateAction` — navigate home:
   ```tsx
   const navigate = useNavigate()
   const handleEmptyStateAction = useCallback(() => navigate('/'), [navigate])
   ```

**Validation**:
- [ ] Every callback calls exactly one use case with the four deps.
- [ ] `ChangeCartItemQuantity` reads the current quantity from the cart and adds/subtracts 1 (never passes an absolute value it doesn't compute).
- [ ] No closure captures stale state (deps arrays correct — `eslint-plugin-react-hooks` will flag this).

## Subtask T014 — Handle `InitiateCheckout` outcomes

**Purpose**: FR-010. On success open the success modal (cart is already cleared by the use case transitioning cart state); on stock_conflict open the existing modal; on empty_cart/invalid_state no-op (logged via the diagnostics subscription from WP06).

**File**: `src/app/containers/cart-container.tsx` (continue).

**Steps**:

1. Local state for the two modals:
   ```tsx
   const [successOpen, setSuccessOpen] = useState(false)
   const [conflict, setConflict] = useState<StockConflict[] | null>(null)
   ```

2. Checkout handler:
   ```tsx
   const handleCheckout = useCallback(() => {
     InitiateCheckout(cartRepo, stockRepo, eventBus).then((result) => {
       if (result.success) {
         setSuccessOpen(true)
         return
       }
       if (result.reason === 'stock_conflict') {
         // Enrich conflicts with imageUrl from productsData for the modal
         const enriched: StockConflict[] = result.conflicts.map((c) => ({
           ...c,
           imageUrl: productsBySku.get(c.skuId)?.imageUrl,
         }))
         setConflict(enriched)
         return
       }
       // empty_cart | invalid_state → no-op (logged by diagnostics subscription)
     })
   }, [cartRepo, stockRepo, eventBus, productsBySku])
   ```

3. `isCheckoutDisabled` — disabled when cart is empty (prevents the empty-cart checkout path per spec Edge Cases):
   ```tsx
   const isCheckoutDisabled = cart.items.size === 0
   ```

4. Render the page with all derived props, plus the two modals at the end:
   ```tsx
   return (
     <>
       <CartPage
         items={items}
         subtotal={subtotal}
         discount={discount}
         shipping={shipping}
         total={total}
         appliedCoupon={appliedCoupon}
         couponError={couponError}
         onIncrement={handleIncrement}
         onDecrement={handleDecrement}
         onRemove={handleRemove}
         onApplyCoupon={handleApplyCoupon}
         onRemoveCoupon={handleRemoveCoupon}
         onCheckout={handleCheckout}
         onEmptyStateAction={handleEmptyStateAction}
         isCheckoutDisabled={isCheckoutDisabled}
       />
       <CheckoutSuccessModal
         open={successOpen}
         onClose={() => setSuccessOpen(false)}
       />
       <StockConflictModal
         open={conflict !== null}
         conflicts={conflict ?? []}
         onAcknowledge={() => setConflict(null)}
       />
     </>
   )
   ```

**Validation**:
- [ ] Success path: modal opens; the cart empty-state appears behind it (because `InitiateCheckout` transitions cart state and the use case clears items).
- [ ] Stock conflict: the existing `StockConflictModal` opens with enriched `imageUrl`s.
- [ ] Empty-cart/invalid: no UI change (no error surfaced).
- [ ] `isCheckoutDisabled` is `true` when `cart.items.size === 0`.

## Risks & Reviewer Guidance

- **Risk**: Using `coupon.amountCents` or `coupon.discountAmount.cents` directly instead of `calculateDiscount`. **Reviewer**: confirm the discount comes from `coupon.calculateDiscount(subtotalMoney, now)`.
- **Risk**: Reconstructing numbers from formatted strings (the cardinal sin of this mission — SC-004). **Reviewer**: every currency string is the **output** of `Money.fromCents(...).format()`; none is an input to a numeric computation.
- **Risk**: Stale closures in `useCallback` (especially `handleIncrement` reading `cart`). **Reviewer**: confirm `cart` is in the deps array; react-hooks linting will catch this.
- **Risk**: Double-rendering the success modal state on StrictMode. **Reviewer**: state is in the component, not an effect, so StrictMode is fine.
- **Risk**: Forgetting to enrich `StockConflict` with `imageUrl` for the modal. **Reviewer**: confirm the `imageUrl` is joined from `productsBySku`.
- **Risk**: Blocking the click handler with `await`. **Reviewer**: handlers call `.then()` rather than awaiting, so the UI stays responsive; the store update drives the re-render.
