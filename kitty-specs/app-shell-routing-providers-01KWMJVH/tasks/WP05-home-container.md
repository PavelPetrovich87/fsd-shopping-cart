# WP05 — Home Container

## Objective

Compose a responsive product grid (matching the existing `HomePage` layout) inside the app layer, wiring each `ProductCard`'s `onAddToCart` to the `AddToCart` use case via the injected dependencies. Handle the out-of-stock case on the card (FR-011).

This WP is the add-to-cart half of US-1.

## Context

**Why not just modify `HomePage`**: C-004 forbids changing the presentational `HomePage` boundary (it's a no-props pure component from the prior pages mission). The container approach keeps `HomePage` untouched and puts the wiring in the app layer, which is the correct FSD location for "compose presentational things with use cases".

**Codebase facts** (verified 2026-07-03):

- `HomePage` (`src/pages/home/ui/home-page.tsx`) renders:
  ```tsx
  <main className="mx-auto max-w-6xl px-4 py-8">
    <h1 ...>Products</h1>
    <div className="grid grid-cols-1 gap-6 md:grid-cols-2 lg:grid-cols-3">
      {mockProducts.map((p) => <ProductCard key={p.skuId} {...p} />)}
    </div>
  </main>
  ```
  Your `HomeContainer` should reproduce this layout exactly so the UI is visually identical, only with the add-to-cart button enabled.
- `mockProducts` lives at `@/shared/mocks` and is the same data `HomePage` uses. **Note**: `mockProducts` is the `MockProduct` shape consumed by `ProductCard` (it already maps `listPriceCents`/`salePriceCents`). Use it directly.
- `ProductCard` (after WP02) accepts an optional `onAddToCart?: () => void`.
- `AddToCart(skuId, quantity, cartRepo, stockRepo, eventBus)` from `@/features/cart-actions` returns:
  - `{ success: true; cart; event }`, or
  - `{ success: false; error }` where `error.type ∈ { 'InsufficientStockError', 'StockConflictError', 'CartNotModifiableError', 'ItemNotFoundError' }`.
- `useAppDeps()` from `@/app` (WP01) provides `{ cartRepo, stockRepo, couponRepo, eventBus }`.

## Subtask T016 — Wire `onAddToCart` to `AddToCart` use case; handle out-of-stock

**Purpose**: FR-005 (add via use case) and FR-011 (out-of-stock = no add + visual indicator).

**File**: `src/app/containers/home-container.tsx` (continue).

**Steps**:

1. Acquire deps and track which skus failed to add:
   ```tsx
   const { cartRepo, stockRepo, eventBus } = useAppDeps()
   const [outOfStockSkus, setOutOfStockSkus] = useState<Set<string>>(() => new Set())
   ```

2. Per-card handler factory. Each card needs its own callback bound to its `skuId`:
   ```tsx
   const handleAdd = useCallback(
     (skuId: string) => {
       AddToCart(skuId, 1, cartRepo, stockRepo, eventBus).then((result) => {
         if (result.success) {
           setOutOfStockSkus((prev) => {
             if (!prev.has(skuId)) return prev
             const next = new Set(prev)
             next.delete(skuId)
             return next
           })
           return
         }
         if (result.error.type === 'InsufficientStockError' || result.error.type === 'StockConflictError') {
           setOutOfStockSkus((prev) => new Set(prev).add(skuId))
         }
         // CartNotModifiableError / ItemNotFoundError → no-op (should not happen on Home)
       })
     },
     [cartRepo, stockRepo, eventBus],
   )
   ```

3. Render each card with its callback. When a sku is in `outOfStockSkus`, omit `onAddToCart` so WP02's card simply does not render the button — that is the "out of stock" indicator (the card without a button communicates unavailability; the existing `PriceBlock` and image remain):
   ```tsx
   {mockProducts.map((product) => {
     const isOut = outOfStockSkus.has(product.skuId)
     return (
       <ProductCard
         key={product.skuId}
         {...product}
         onAddToCart={isOut ? undefined : () => handleAdd(product.skuId)}
       />
     )
   })}
   ```

   **Alternative (richer indicator)**: If you want a visible "Out of stock" label rather than a missing button, that would be a *new* visual state on the card — out of scope (C-007). Stick with omitting the callback; the spec accepts "disabled add button or visible out-of-stock indicator" (FR-011). Omitting the callback is the lighter touch and does not require changing `ProductCard` further.

4. **Recovery**: if the user later removes items from the cart (freeing stock), the next successful `AddToCart` clears the sku from `outOfStockSkus` (handled in step 2's success branch).

**Validation**:
- [ ] Clicking add on a normal product calls `AddToCart(skuId, 1, ...)` and on success the badge (WP03) increments within one render cycle (US-1 scenario 1).
- [ ] When `AddToCart` returns `InsufficientStockError`/`StockConflictError`, the card's button disappears and the cart badge does **not** change (FR-011).
- [ ] After a successful add for a previously-out-of-stock sku, the button reappears.
