# WP06 — Event Subscriptions

## Objective

Two app-level event subscriptions mounted once at the composition root:

1. **CheckoutSubscription** — on `CheckoutInitiated`, perform the canonical reserve-then-confirm stock depletion for each line item and persist the result.
2. **DiagnosticsSubscription** — log all cart domain events for observability; no business logic; separable without changing observable behaviour.

## Context

**Codebase facts** (verified 2026-07-03):

- The `EventBus` API: `subscribe<T extends DomainEvent>(eventType: T['eventType'], handler: Handler<T>): Unsubscribe`. The `eventType` argument is the string discriminator (e.g., `'CheckoutInitiated'`). `publish` fires handlers asynchronously via `Promise.resolve().then(...)`.
- `CheckoutInitiated` event (from `@/features/checkout`):
  ```ts
  interface CheckoutInitiated {
    eventType: 'CheckoutInitiated'
    cartId: string
    userId: string
    items: readonly CartItem[]   // each: { skuId, name, unitPriceCents, quantity, createdAt }
    subtotal: Money
    timestamp: Date
  }
  ```
- Stock operations (from `@/entities/product`):
  - `reserve({ variant, orderId, quantity }) → { variant: ProductVariant; event?: StockReserved; depletedEvent?: StockDepleted }`
  - `confirmDepletion({ variant, orderId }) → { variant: ProductVariant; event?: StockDepleted }`
- **Critical** (research.md R-01): `confirmDepletion` does **not** take a quantity. It looks up the reservation on `variant` matching `orderId` and permanently subtracts that reservation's quantity. **If no reservation exists, the variant is returned unchanged.** Therefore the subscription MUST call `reserve` first, then `confirmDepletion`, per line item.
- `IStockRepository` (from `@/entities/product`): `findBySku(skuId) → Promise<ProductVariant | null>`, `save(variant) → Promise<void>`. Note `MockInventoryRepository.save` is currently a no-op (`void variant`) — that's expected for this mission; the depletion is performed in-memory and the result is what matters for the same-session experience. Do not "fix" the mock.
- `useAppDeps()` from `@/app` (WP01) provides `{ eventBus, stockRepo, ... }`.
- Cart domain event types (for diagnostics) are exported from `@/entities/cart`: `'ItemAddedToCart'`, `'CartItemQuantityChanged'`, `'ItemRemovedFromCart'`, `'CartCleared'`, `'CheckoutInitiated'`, `'CheckoutCompleted'`, `'CouponApplied'`, `'CouponRemoved'`. The event-bus `subscribe` is per-event-type, so to log "all cart events" you subscribe once per type.

## Subtask T017 — Create `CheckoutSubscription` (reserve + confirmDepletion + save)

**Purpose**: FR-008 — turn a `CheckoutInitiated` event into actual stock depletion.

**File**: `src/app/subscriptions/checkout-subscription.tsx` (new).

**Steps**:

1. Imports:
   ```tsx
   import { useEffect } from 'react'
   import { reserve, confirmDepletion } from '@/entities/product'
   import type { CheckoutInitiated } from '@/features/checkout'
   import { useAppDeps } from '@/app'
   ```

2. The depletion function for one event. `orderId` is derived from `event.cartId` (the cart's lifetime identity; there's no separate order id in this in-memory model):
   ```tsx
   async function depleteStockForCheckout(
     event: CheckoutInitiated,
     stockRepo: import('@/entities/product').IStockRepository,
   ): Promise<void> {
     const orderId = event.cartId
     for (const item of event.items) {
       const variant = await stockRepo.findBySku(item.skuId)
       if (!variant) continue
       const { variant: reserved } = reserve({ variant, orderId, quantity: item.quantity })
       const { variant: depleted } = confirmDepletion({ variant: reserved, orderId })
       await stockRepo.save(depleted)
     }
   }
   ```

3. The React component that subscribes on mount and unsubscribes on unmount:
   ```tsx
   export function CheckoutSubscription() {
     const { eventBus, stockRepo } = useAppDeps()
     useEffect(() => {
       const handler = (event: CheckoutInitiated) => {
         // fire-and-forget; errors are logged, not surfaced (the cart is already checked out)
         depleteStockForCheckout(event, stockRepo).catch((err) => {
           console.error('[CheckoutSubscription] depletion failed', err)
         })
       }
       const unsubscribe = eventBus.subscribe('CheckoutInitiated', handler)
       return unsubscribe
     }, [eventBus, stockRepo])
     return null
   }
   ```

4. **Why the `catch`**: a thrown handler error is already swallowed by `EventBus.publish` (it logs), but the depletion is async-after-publish — wrap it so an unhandled rejection never escapes.

**Edge case — partial reserve**: `reserve` calls `Math.min(quantity, currentAvailable)` internally. If stock is insufficient at subscription time (race), it reserves whatever is available and `confirmDepletion` depletes that amount. `InitiateCheckout` already validated stock sufficiency before publishing, so partial depletion only occurs under a true race (acceptable per research.md R-01).

**Validation**:
- [ ] After `InitiateCheckout` succeeds, every cart line's variant has its `totalOnHand` reduced by the reserved quantity (verifiable via `stockRepo.findBySku` in a test).
- [ ] Unmounting the component removes the handler (a second mount does not double-subscribe).

## Subtask T018 — Create `DiagnosticsSubscription` (logging-only cart-event handler)

**Purpose**: FR-009 — a separable observability handler. Must not contain business logic.

**File**: `src/app/subscriptions/diagnostics-subscription.tsx` (new).

**Steps**:

1. Imports:
   ```tsx
   import { useEffect } from 'react'
   import { useAppDeps } from '@/app'
   ```

2. The list of cart event types to observe (from `@/entities/cart`):
   ```tsx
   const CART_EVENT_TYPES = [
     'ItemAddedToCart',
     'CartItemQuantityChanged',
     'ItemRemovedFromCart',
     'CartCleared',
     'CheckoutInitiated',
     'CheckoutCompleted',
     'CouponApplied',
     'CouponRemoved',
   ] as const
   ```

3. Component — subscribe to each type with the same logging handler:
   ```tsx
   export function DiagnosticsSubscription() {
     const { eventBus } = useAppDeps()
     useEffect(() => {
       const handler = (event: { eventType: string }) => {
         console.debug('[cart-event]', event.eventType, event)
       }
       const unsubscribers = CART_EVENT_TYPES.map((type) =>
         eventBus.subscribe(type, handler),
       )
       return () => {
         for (const unsub of unsubscribers) unsub()
       }
     }, [eventBus])
     return null
   }
   ```

4. **Separability**: removing this component must not change any observable business behaviour. It only `console.debug`s.

**Validation**:
- [ ] Every cart action logs a `[cart-event] ...` line.
- [ ] Unmounting unsubscribes from all 8 event types.

## Risks & Reviewer Guidance

- **Risk**: Calling `confirmDepletion` without a prior `reserve` (the reservation would not exist, so depletion silently no-ops). **Reviewer**: confirm the per-item sequence is `reserve → confirmDepletion → save`.
- **Risk**: Forgetting to unsubscribe on unmount, causing handlers to accumulate under StrictMode's double-mount-in-dev. **Reviewer**: confirm `useEffect` returns the unsubscribe(s).
- **Risk**: Putting business logic in the diagnostics handler. **Reviewer**: it must contain only `console.debug`. No state, no conditionals, no calls into repos.
- **Risk**: Subscribing to `CheckoutInitiated` in *both* subscriptions and having one cancel the other. **Reviewer**: the event bus supports multiple handlers per event type; both fire. That's fine and intended (FR-008 + FR-009 are separable concerns on the same event).
- **Risk**: Awaiting the depletion inside the bus handler synchronously and breaking the bus's fire-and-forget contract. **Reviewer**: confirm the handler calls `.then`/`.catch` rather than `await`-in-handler.
