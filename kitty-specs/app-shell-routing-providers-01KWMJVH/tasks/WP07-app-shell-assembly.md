# WP07 — App Shell Assembly & Demo Removal

## Objective

Assemble the final `AppShell` from the building blocks produced by WP01–WP06, route it through `src/App.tsx`, delete the demo entry (`src/pages/App.tsx`), and verify every project quality gate. This is the integration WP — it runs last and depends on all the others.

## Context

**Codebase facts** (verified 2026-07-03):

- `src/main.tsx` **already** renders `<BrowserRouter><App /></BrowserRouter>`. **Do not** add a second `BrowserRouter`. WP07 modifies `src/App.tsx` to render `<AppShell />`, full stop.
- Current `src/App.tsx`:
  ```tsx
  import { Routes, Route } from 'react-router-dom'
  import { App as AppPage } from './pages/App'

  function App() {
    return (
      <Routes>
        <Route path="/" element={<AppPage />} />
      </Routes>
    )
  }

  export { App }
  ```
  After WP07, this becomes a one-line render of `<AppShell />`.
- `src/pages/App.tsx` is the demo entry (the 145-line `useState`-routing, hardcoded-items, string-parsing-prototype). It is **not** exported from `pages/index.ts` (only `CartPage` and `HomePage` are). Deleting it touches no public page boundary (C-004 preserved).
- WP01 exports `AppProviders` from `@/app`.
- WP03 exports `AppRoutes` from `@/app/routing/routes` (you may also re-export it from `@/app`).
- WP06 exports `SubscriptionsRoot` from `@/app/subscriptions`.

**FSD constraint** (C-001): `src/app/index.ts` may re-export freely within the slice and from lower layers. `src/App.tsx` (project root `src/`) imports only from `@/app`.

## Subtask T020 — Wire `AppShell` = `<AppProviders><SubscriptionsRoot><AppRoutes /></...>`

**Purpose**: The single composed shell.

**File**: `src/app/index.ts` (extend) **and** a new component file.

**Steps**:

1. Create `src/app/ui/app-shell.tsx` (or place `AppShell` directly in `src/app/index.tsx` — but TS/React JSX in a `.ts` file is disallowed; use a `.tsx` file). Preferred: `src/app/ui/app-shell.tsx`:
   ```tsx
   import { AppProviders } from '../providers/app-providers'
   import { SubscriptionsRoot } from '../subscriptions'
   import { AppRoutes } from '../routing/routes'

   export function AppShell() {
     return (
       <AppProviders>
         <SubscriptionsRoot />
         <AppRoutes />
       </AppProviders>
     )
   }
   ```

2. **Order matters**: `<AppProviders>` must be outermost (it provides the context both `SubscriptionsRoot` and `AppRoutes` consume). `SubscriptionsRoot` and `AppRoutes` are siblings — order between them doesn't matter since they don't communicate via React tree, but subscriptions mounting before routes is conceptually cleaner.

3. Re-export from `src/app/index.ts`:
   ```ts
   export { AppProviders } from './providers/app-providers'
   export type { AppProvidersProps } from './providers/app-providers'
   export { useAppDeps, AppDepsContext } from './providers/app-deps'
   export type { AppDeps } from './providers/app-deps'
   export { AppShell } from './ui/app-shell'
   ```

   (Merge with whatever WP01 already wrote in this file — keep all existing exports, add `AppShell`.)

**Validation**:
- [ ] `<AppShell />` renders without errors when wrapped by `<BrowserRouter>` (the routes need it).
- [ ] Exactly one `EventBus` and one of each repo are created across the session (NFR-007).
